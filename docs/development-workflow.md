# Git Worktree + 자동 QA 작업 방식

이 프로젝트는 **약국 ERP를 중심으로, BI와 정보 화면을 붙이는 구조**로 운영합니다. 업무 기록을 다루는 화면과 분석·외부정보를 한 작업에서 섞어 고치지 않으면, 에이전트 작업도 안전하고 검수도 쉬워집니다.

## 역할과 브랜치

| 작업 영역 | 담당 범위 | 브랜치 예시 |
| --- | --- | --- |
| ERP | 판매·입고·재고·반려동물·공유 업무의 입력/조회 흐름 | `feature/erp-sales-history` |
| BI | 매출·수익 분석, 추이, 예측, 분석용 화면 | `feature/bi-profit-view` |
| 정보 | 대시보드 뉴스·정책·건강 정보의 문구와 출처 | `feature/content-dashboard-news` |
| QA | 테스트, 접근성·반응형 점검, 재현 절차 | `qa/qa-release-check` |

`main`은 배포 가능한 상태만 두는 브랜치입니다. 한 작업공간에서 여러 역할을 동시에 고치지 말고, 요청 하나는 하나의 역할 브랜치에서 처리합니다. 현재 `app.js`가 큰 파일이므로 **한 배치에서 `app.js`를 수정하는 구현 작업은 한 명만** 맡습니다. 다른 역할은 검토·테스트·문서 작업으로 병렬화하면 충돌이 줄어듭니다.

## 새 작업공간 만들기

먼저 `main` 작업공간에서 최신 변경을 받은 뒤 실행합니다.

```powershell
git pull --ff-only origin main
.\tools\new-worktree.ps1 -Area erp -Name sales-history
```

작업공간은 저장소 바깥의 형제 폴더에 생깁니다. 예를 들어 `E:\kumin-pharmacy-worktrees\erp-sales-history`입니다. 원본 작업 폴더의 파일·로그·개인 설정을 복사하지 않으므로, 각 작업공간에서 아래를 한 번 실행합니다.

```powershell
cd E:\kumin-pharmacy-worktrees\erp-sales-history
npm ci
```

`-Area`는 `erp`, `bi`, `content`, `qa` 중 하나이며 이름은 영문 소문자·숫자·하이픈으로 씁니다. 도구는 기존 브랜치나 폴더를 덮어쓰지 않습니다. 작업공간 정리는 병합이 끝난 뒤 담당자가 경로를 확인하고 별도로 수행합니다.

## 자동 QA 루프

PR을 열면 GitHub Actions의 **Read-only QA**가 다음만 자동 검사합니다.

1. `app.js` 문법과 대시보드 뉴스 출처/다운로드 차단 규칙
2. 비밀 설정 없이 로컬 정적 화면이 열리는지
3. 로그인 전 뉴스·업무 정보가 보이지 않는지

이 검사는 데이터베이스에 로그인하거나 데이터를 만들지 않습니다. 배포 워크플로도 같은 QA를 먼저 통과해야 Pages 빌드를 시작합니다.

개발자는 커밋 전에도 다음 한 줄을 실행합니다.

```powershell
npm run qa:ci
```

실제 계정과 업무 데이터를 쓰는 판매 등록·공유 업무·권한 검증은 자동 PR 검사에 넣지 않습니다. 운영 데이터를 건드릴 위험이 있으므로, 별도 로컬 검수에서 **읽기 전용 계정과 테스트 전용 데이터**가 준비된 경우에만 실행합니다. `sales-pet-link`처럼 데이터를 생성할 수 있는 기존 테스트는 PR 자동 QA에 포함하지 않습니다.

## 에이전트 작업 순서

1. 고객 역할 에이전트가 해당 역할의 업무 흐름과 화면 크기(데스크톱·태블릿·모바일)를 확인해 문제를 기록합니다.
2. 기획/디자인 검토는 문구, 버튼 대비, 글자 크기, 입력 횟수만 검토합니다.
3. 구현 에이전트가 한 영역 브랜치에서 작은 수정만 합니다.
4. QA 역할이 `npm run qa:ci`와 수정한 화면 흐름을 다시 확인합니다.
5. PR에는 변경 화면, 확인한 흐름, 테스트 결과, 남은 위험만 짧게 적습니다. 통과 후에만 `main`으로 병합합니다.

GitHub 저장소 설정에서는 `main`에 대해 PR 필수, **Read-only QA 필수 통과**, 직접 push 제한을 켭니다. 이는 한 사람이 급하게 수정해도 검수 단계를 건너뛰지 않게 하는 마지막 장치입니다.

## 비밀정보와 운영 안전

`.env`, `config.js`, `test-accounts.local.json`, 실제 고객 엑셀은 공유·커밋·PR 로그에 넣지 않습니다. 자동 QA는 빈 테스트 설정만 임시로 만들며, 실제 Supabase 주소나 계정에는 연결하지 않습니다. 외부 뉴스 링크는 허용 출처와 다운로드 경로 차단 검사를 유지합니다.
